# Frontend

No build step. `index.html` (markup, export dialog, setup container; styles in `static/m3.css` and `static/app.css`) loads `/static/hls.min.js` (local copy), `/static/app.js?v=NN` and `/static/setup.js?v=NN` (query strings at the end of index.html; bump on every change, the server also sends no-cache for `/` and `/static`). Both scripts are classic scripts sharing one global scope: `setup.js` must not redeclare a top-level name of `app.js` (`$`, `v`, `cam`, `W`, `T`, ...). The server serves only the files in `STATIC_FILES` (server.py).

Design tokens: `static/m3.css` is generated by `tools/m3_palette.py` (dev-only, needs `materialyoucolor`; do not edit the CSS by hand) and checked by `tools/check_m3_contrast.py` (stdlib, WCAG 4.5:1 text, 3:1 outline). `index.html` loads it first (`/static/m3.css?v=1`), then `static/app.css?v=1` (the page styles, moved out of `index.html`: app bar with the camera tabs, player, sheets; new rules use the `--md-sys-*` tokens directly). `m3.css` carries compatibility aliases for the `--c-*` tokens.

## Setup wizard and Settings (static/setup.js, W4; UI rebuilt W15b)
- **Gate on load:** `app.js` `init()` lists only cameras that are `enabled && verified` as playable (`okCam`). `setup.js` `boot()` reads `/api/cameras` and `/api/setup/state`: with no playable camera the setup (`#setup`) is shown instead of the player (`#app` hidden); otherwise the timeline runs and the gear (`#settingsbtn`, which opens Settings directly) is shown.
- **Views** (`VIEWS`, `SU.view`): the wizard has four steps (`SU_WIZARD`, four progress segments): `prepare` (checklist, "This computer" line or the missing items, disclaimer; Continue), `account` (TP-Link account: one saved row with Change, or the form; Save and continue; never signs in), `add` ("Find cameras on my network" disclosure `discoverBox`: subnet prefilled from `GET /api/setup/discover`, scan via `POST`, found addresses with Use via `useFound`; rows of name, address and an optional "Live view (optional)" disclosure; `addBatch` validates every row, then `POST /api/setup/cameras` one by one, stopping at the first error; then `checkAllReach` (`POST /api/setup/reach`, login-free) shows "Found on your network" or "No answer" inside each card with the ports under Details), `verify` (one card per camera from `camState`; `POST /api/setup/verify` one press at a time, countdown from `wait_s`; "Add another camera" sits in the body under the cards; the footer is Back, the reason (when Open timeline is off) and "Open timeline", enabled only when a camera is playable). `done` is merged into `verify` (`go('done')` maps to it). `settings` is the master-detail page.
- **Settings** (`viewSettings`, `SU.sel`): desktop (>= 720px) one sidebar (`.su-side`, 280px; 240px at 720-959px) with groups Cameras (one row per camera, then Add camera) and General (TP-Link account, This computer, About; group labels are divs named by `aria-labelledby`, so the pane title is the first heading), and one detail pane (`.su-pane`, max 720px). Camera pane (`paneCamera`): identity (`identity`: name with Rename, chip from `camState`, the one state action, Turn off when Ready, one alert); Connection (`connectionCard`: address with Change (a verified camera asks first, `confirmDialog`), model reported by the device, sign-in); Live view (`liveCard`: the camera account row, saved as user and masked password, Change; refused by the camera: chip "Not accepted"); Order (two or more cameras: on a wide screen the selected sidebar row carries up and down arrow buttons (`moveButton`, in `.su-row-wrap`, a sibling of the row button); on a phone the pane has an Order section (`orderCard`, "Camera N of M", Move up and Move down); the end that cannot move is disabled; `moveCam` does `PUT /api/cameras/order` with `movedOrder`, shows Saved, and sets `SU.changed` so closing reloads the player; focus goes to the button still enabled); Playback (`playbackCard`: switches `role=switch` saved on change, Fast-forward with its hint, the Pan and tilt switch only for C200/C210 or with PTZ on, Invert and step only with PTZ on; one `<details>` for Details holds the clip piece length (120px input, saved on Enter or blur) and the dl); Remove (`removeCard`, confirm dialog). Add camera is the `new` pane (`paneNew`, one row via `addSingle`, Cancel reselects the previous camera). Account, This computer (Appearance: a radio group, `themeKeys`; Video tools and Saved passwords sections from `prereqRows`, with an install or help link and no file names; the port line) and About (the lead, the Version row from `/api/setup/state` `version` = `config.VERSION`, the legal line) are their own panes. On a phone's detail screen the header shows the item's name (`paneTitle`); the back button reads Settings. Phone (< 720px): list screen, then the detail screen with "‹ Settings" as its back button and the item's name as the header title; `pushState` on entering, `backToList` and `onPop`.
- **Edit mode:** one row at a time (`SU.edit`: `name:<id>`, `addr:<id>`, `live:<id>`, `acct`); `startEdit` / `endEdit` return focus to `SU.opener` (a `data-focus` key). Escape ends an edit, then (desktop, nothing open) closes Settings. Focus is restored after each re-render by its `data-focus` key (`renderView`).
- **Card state** (`camState`, pure, wizard-ui-v2 table): one chip, at most one alert, one action. The page's own Verify result (`SU.vs`) comes before the server gate state, so a refusal reads "Sign-in refused" at once and "Paused" after a reload. `liveRow` gives the Live view row. `pickSelection` picks the default camera.
- **Messages:** field errors under the field (`setErr`, `labelled`; no `role=alert`); object errors under their row (`SU.errs`, `errAt`, no `role=alert`); "Saved" inline in the row's value once and cleared after 3 s (`SU.saved`, `savedTag`); one toast for success only (`toast`, with Undo for Turn off; focus inside it stops the timer). The remove-failed message shows in the This computer pane. Confirm dialogs (`confirmDialog`, `dialogCopy`) for Remove, a new address on a verified camera and Use automatic sign-in. No banner, no `.su-flash`.
- **Automatic model apply:** a Verify that finds another model applies the device's preset silently (`modelFixBody`, `PATCH` with `apply_preset`). No model question is asked anywhere.
- **Gate rules:** Verify only on a press, one camera at a time (`verifyHold`), a refused TP-Link password stops the run (`SU.authStop`, `isAuthFailure`). A save never signs in. No credential notice except the unreadable store, under This computer.
- **Closing:** a successful change sets `SU.changed`; closing (Timeline) reloads the page so the timeline reads the new list, otherwise focus returns to the gear (`#settingsbtn`).
- **Waits:** `tickCountdowns` (1 s) updates the `data-until` text and the draining `.su-bar-fill` only; a wait that ends redraws the page unless a text field has focus.
- **DOM rule:** all text is set with `textContent` (the `h()` helper), icons from `icon()` (SVG via `createElementNS`). No `innerHTML` with data, no `style=` attribute, no inline `on*` handler (CSP): events use `addEventListener` through `h()`; the wait bar's `--frac` is set with `style.setProperty` from script.
- **Layout:** `#suwrap` is one card (max 560px, no fixed height, no inner scroll) in the wizard; the footer `#setupfoot` is sticky to the bottom of the page and holds the step's `.su-nav` (Back on the left, actions on the right). Settings is full width (`#suwrap.settings`, sticky 64px bar). Spacing: blocks 20 or 32 apart (`.su-view`, `.su-set`, `.su-pane-in`), fields 20 (`.su-stack`), inside a card 16 to 20 (`.su-card-s`, `.su-pad`).
- **Other devices** (`paneDevices`, selection `devices`, General group after This computer; no subtitle: the sidebar row is plain): sharing radio (`sharingGroup`, PUT `/api/setup/sharing`; a command-line start shows fixed text), Address (`addressBox`: one `.su-card-s` row: the address, then a QR icon button (`data-focus` qr-open, aria-label and title "Show QR code", icon `qr`, 36px as Copy) and Copy (`copyAddress`). The QR button opens the one Settings dialog `#suconfirm` through `openQr` ("Open on your phone": a 260px `img` of GET `/api/setup/devices/qr?a=<address>` on the white token `--c-qr`, the address in mono, the Wi-Fi hint, one ghost Close; focus to Close, back to the QR button on close; `dlg.dataset.qr` holds the address shown). The refresh (`loadDevices`) closes it when the address changes or sharing turns off (`closeQrIfStale`); `redrawDevices` waits while it is open; an image that fails becomes a hint; no card without an address), Waiting for approval (`pendingBox`: Allow adds with an empty name and toasts with Undo; Dismiss), Allowed devices (`allowedBox`: Remove with Undo, command-line entries read-only), Add a device (`addDeviceArea`: a ghost button under the list; it opens `addDeviceForm` in place as `SU.edit = 'device-add'` through `openDeviceForm`, focus goes to the IP field; Cancel and Escape collapse it through `endEdit`, which drops the draft; a successful add collapses it and toasts; a real submit button so Enter adds; the draft lives in `SU.devForm`, so a refresh keeps typed text and the form stays open). Every action applies the whole answer (`applyDevices`); errors sit under their row (`SU.errs.sharing|address|pending|list|add`); opening the add form clears only `SU.errs.add` (`startEdit`). `SU.devForm` (the draft) is dropped by `endEdit`, `go`, `selectPane` and `closeSetup`. The list is re-read every 5 s while this pane is open (`devicesTick`, guarded by `devicesVisible`); a redraw waits while a text field has focus (`redrawDevices`, `SU.devDirty`); "tried to connect N min ago" is repainted each second (`paintSeen`).
- **Markers:** the pure logic sits between `/* setup-logic:begin */` and `/* setup-logic:end */` in `static/setup.js`: sign-in text, countdown, validators (IP, address, name, email, secret, number range), verify hold, refusal test, friendly texts, card state (`camState`), Live view row (`liveRow`), selection, verify title and lead, camera order (`movedOrder`), footer reason, dialog copy, model fix body, the account plan, add rows and the batch (`runAddBatch`), prerequisite rows. `tests/test_setup_logic.js` loads it into a `vm` context and fails if the block touches the DOM, network or storage.
- **Not verified here:** no browser test exists for the DOM code (no jsdom in the repo). Syntax is checked with `node --check`. Layout and focus were checked with a throwaway DOM shim outside the repo (not committed).

## Invariants
- The two policy blocks are pure functions read by `tests/test_prefetch.js` through their marker comments. Keep the markers and keep the blocks free of DOM access.
- Speed model: P2P cameras with `ff` stream every speed (`scale = rate + "/1"`); direct `ff` cameras stream 8x/16x and use full clip pieces for <= 4x. The timeline factor is the scale numerator (`ffViewT`). Changing speed restarts the stream only when the scale changes.
- Camera flags come from `/api/cameras` (`thumbs`, `stream`, `ff`, `win`, `ptz`).

## cameras.json keys (read by the server, mirrored by `/api/cameras`)
| Key | Meaning | Read at |
|---|---|---|
| `id`, `name`, `ip`, `enabled` | identity; `enabled:false` -> BadInput | `session.py` |
| `auth` | `auto` (default: the app's own login, user `admin` and the TP-Link password, on TPAP and on the legacy transport; the camera account is not used), `admin_cloud` (the same login, for older cameras), or `cam_cloud` (user and camera password, for older cameras); anything else is BadInput | `session.build` |
| `ptz` | pan/tilt buttons and `/api/ptz` | `services/ptz.py`, `app.js` |

| `stream_playback` | HLS playback; exposed as `stream` | `services/play.py`, `server.require_stream` |
| `fast_forward` | allows key-frame scales; exposed as `ff` | `server.require_stream` |
| `thumbs` | `false` -> `/api/thumb` returns 404 (unless `native_thumbs` and `p2p`) | `server.thumb`, `app.js` |

| `win` | clip piece length in seconds (client only) | `app.js` |
| `ptz_step_deg`, `ptz_invert` | optional PTZ tuning (defaults 10 and off) | `services/ptz.py` |
